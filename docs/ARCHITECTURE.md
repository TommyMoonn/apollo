# Apollo Architecture

> [!IMPORTANT]
> All of the documentation here are written by LLMs.

Apollo is a native Windows x64 media utility written in Rust. GPUI is the native application entry, and FFmpeg and FFprobe run as separate child processes. Media stays on the user's machine. The application has no web frontend, server or account dependency.

The GPUI migration is in progress. The root owns one `Application`, starts media-tool discovery and settles worker notifications on the UI thread regardless of navigation. Its shared shell integrates source intake, operation selection, Queue and Settings navigation, discovery, queue activity and shutdown state. Queue controls, operation forms, batch configuration and appearance settings remain disabled until their presentation phases. The retained egui implementation below describes the existing behavior contracts and regression tests, not an alternative runnable application.

## Module boundaries

| Area | Responsibility |
| --- | --- |
| `src/main.rs`, `src/ui/root.rs` | GPUI entry, native window configuration and root entity owning one `Application`. |
| `src/app/` | `Application`: renderer-independent route state, dialog requests, preferences, media-tool discovery, source intake, interactive frame coordination, queue. |
| `src/ui/legacy/` | Retained egui adapter contracts, editors, worker coordination and tests awaiting migration. |
| `src/ui/` | Operation views, shared widgets, queue and batch views, layout, themes and typography. |
| `src/media/` | Source inspection, media models, tool discovery, process lifecycle, progress and output publication. |
| `src/queue/` | Queued requests, job identity and execution order. |
| `src/audio_mix/`, `src/upscale/`, `src/remux/`, `src/audio_extract/`, `src/frame_capture/` | Operation requests, validation, command construction and execution. |
| `src/settings.rs` | Typed remembered-directory preferences, atomic JSON persistence and fallback policy. |
| `src/file_dialog.rs`, `src/native.rs` | Native dialog service, parent window handles and shell folder actions. |
| `src/app/background.rs` | Foreground worker settlement and bounded wake channel. |
| `src/progress_wake.rs` | Renderer-neutral progress coalescing. |

The library exports the application core and UI modules through `src/lib.rs`. The native binary creates one GPUI root with exactly one core. The core does not import UI or native adapters. Keep operation policy in its domain module and use the shared media and queue owners. Views display state and collect input; repainting must not start probes or processing.

The retained presentation modules have explicit migration owners: U01.2 establishes GPUI theme, layout, fonts and shared controls without removing the retained egui consumers; U01.3 replaces background wake and shutdown coordination; U01.4 replaces native-dialog routing and preferences; U01.5 and U01.6 replace intake and workspace navigation; U02 replaces queue presentation; U03–U05 replace operation forms and frame capture; U06 replaces batch presentation; U07 replaces settings presentation. Keep the existing regression tests until equivalent GPUI or core behavior tests cover their contracts.

## Native GPUI foundation

`src/ui/design.rs` owns GPUI color, typography and geometry roles. `src/ui/components.rs` implements reusable stateless controls, and `src/ui/shell.rs` owns shared page geometry and scroll fallback, and `src/ui/root.rs` composes the active route. The [UI design guide](DESIGN.md) defines their contracts. The older egui `theme`, `fonts`, `layout` and `widgets` modules remain solely for retained views and tests.

The entry uses official Zed [`gpui` and `gpui_platform` at v1.29.3 (d01b134)](https://github.com/zed-industries/zed/tree/d01b134cddf5e4f71964deb2d6f81cdb38fcf1e7), pinned to the same Git commit rather than a fork or moving branch. `gpui_platform::application()` selects the native Windows backend. The window is opaque and text rendering follows the platform default, allowing DirectWrite ClearType subpixel antialiasing when Windows recommends it. It requests a centered 730 × 489 logical-pixel window and a 400 × 260 minimum, with native chrome and title. The Win32 icon comes from the existing executable resource. No second renderer entry or feature switch is provided.

The pinned API provides `WindowOptions` for sizing and titlebar configuration, `Window::on_window_should_close` for close interception, `Window`'s `HasWindowHandle` implementation for native dialogs, `ExternalPaths` and element drop handlers for intake, `TextSystem::add_fonts` for font registration, and entity `Context::notify` and `spawn` for background-driven presentation. Background settlement and native close interception are connected. Native file dialogs and intake are connected. Native sizing, icon behavior and the full GPUI dependency graph still require Windows acceptance.

## Composition and navigation

`src/app/navigation.rs` owns `Operation`, routes and typed return origins. Queue and Settings share `ShellOrigin` for intake, source workspace and batch setup; no additional navigation stack exists. Switching operations changes the selected identifier without replacing the accepted source or drafts. Background source publication updates a temporary route’s return origin rather than dismissing that route. Queue return and batch submission preserve the original source operation. Queue history and pending counts remain with `MediaQueue`.

`src/ui/legacy/mod.rs` retains the existing egui adapter and its background and shutdown contracts for tests. `render.rs` dispatches retained operation forms, queue and batch views. The retired normal source header is no longer rendered there; `workspace.rs` retains fixed-source editor presentation for U02 and U06. `shutdown.rs` intercepts native close requests and presents the exit decision and settlement status. `source.rs` handles source actions and presentation settlement. The four ordinary operation adapters (`audio_mix.rs`, `upscale.rs`, `remux.rs` and `audio_extract.rs`) own their ready surfaces and translate form actions into queue submissions. `dialogs.rs` routes native completions; `frame_capture.rs` routes frame actions and uploads textures; `queue.rs` translates queue effects into native actions and presentation updates; `batch.rs` presents batch setup and fixed-source editors and routes native actions; `workflows.rs` retains shared route and lifecycle helpers; `state.rs` retains adapter-specific presentation.

The GPUI root subscribes to a capacity-one asynchronous wake channel with a window-scoped foreground task and weak entity handle. The core settles discovery, source inspection, batch inspection and queue notifications without waiting for a render pass. The same shutdown owner cancels and settles workers before window removal. During confirmation, existing work continues; dismissal restores focus. The failure acknowledgement is shown only after all active owners settle. Output-dialog and interactive frame presentation routing remain with their retained adapters until the corresponding GPUI forms migrate.

In the retained adapter, each root update first polls media-tool discovery and queue events. While base tools are checking or unavailable, it renders that status and returns. Once ready, the update polls dialogs, source inspection, batch inspection, frame preview, frame index and clipboard in that order before handling drops and rendering the active route. Normal close is intercepted in the egui logic pass, even when the window is hidden. With unfinished queue work, one confirmation precedes cancellation. Declining leaves the current route, drafts and queue intact. On acceptance, `Application` enters closing, stops advancement through `MediaQueue::cancel_queue`, rejects new submissions and queue actions, and polls terminal notifications until the active execution settles. The renderer requests actual closure only after settlement and after any pending native dialog returns. A failed active job, including a cleanup failure, is reported and must be acknowledged before exit. Dropping an active file execution remains a defensive fallback that stops and joins its child before discarding staged output; forced OS termination is not graceful shutdown.

## Source intake and execution

`src/app/source.rs` owns the accepted source session, its inspection worker and intake errors. `MediaIntake` remains the authority for source identity and probe acceptance. An unsuccessful replacement leaves the accepted session intact; successful replacement or restoration from a queued snapshot creates a new session identifier. Closing a source retires its pending inspection and accepted session without touching queued jobs. Source and independent editor identifiers share one allocation sequence to keep stale worker and dialog results from targeting a different editor.

The legacy source adapter builds one immutable `SourcePresentation` after acceptance or queued-source restoration. All normal operation drafts share the accepted source identifier and retain their settings when switching operations. Independent queue and batch editors keep their own snapshots. Presentation and frame support are retired together when the accepted source changes or closes.

1. `MediaIntake` identifies the source using its canonical path, size and modification time. It reuses a successful inspection only when the identity is reliably unchanged, and retires results from superseded requests.
2. `src/media/probe.rs` invokes FFprobe, parses JSON and normalizes streams into the models in `src/media/model.rs`. `src/media/container.rs` owns shared MP4 and Matroska stream-copy compatibility.
3. Operation drafts validate typed requests against inspected media without filesystem access. Queue admission checks source identity and the output parent before retaining request and media snapshots; batch admission performs the same checks for each item before inserting any job. At launch, the queue rechecks the retained source identity. The queue then calls the same operation-specific preparation functions, which validate requests again rather than trusting draft readiness. Audio Mix reuses the validated channel layout, and Upscale reuses its calculated dimensions, resolved encoder and pixel format when constructing the command. Command builders use the staged destination directly, and `PreparedMediaOperation` configures FFmpeg progress on stdout.
4. `MediaExecution` owns each active file operation and settles its output once. `MediaProcess` owns the child, stream readers, cancellation, bounded stderr diagnostics and progress channels. Cancellation wakes the child polling loop; terminal state is published after the child exits and both readers finish. A reader failure cannot turn a successful exit into a completed operation. `src/media/progress.rs` parses progress records; an unknown duration remains indeterminate, and progress alone cannot establish success.
5. `MediaOutput` checks the destination, owns temporary output and publishes it only after successful processing. At execution start it selects an available numbered name for progress display. The operating system’s no-replace move remains authoritative at publication: if that name becomes occupied, publication tries the next numbered name. Pending jobs provide admission-time destination checks for edits, batches and exact retries; they do not claim filesystem names. Failed or cancelled jobs clean up their own temporary output without overwriting the input or an existing destination. Publication failure is terminal; only cleanup may be retried during disposal. Settlement reports cleanup failure rather than claiming success or cancellation. If publication already won, cleanup never deletes the published file.

All five file-producing operations submit typed requests to the queue. Frame Capture uses Save frame in place of Process now. Process now is available only with no pending queue work and ready tools; it admits once, opens Queue and starts through the scheduler. Add to queue retains the draft and never starts a stopped queue. The queue owns file preparation, execution and output settlement. Completed frame jobs expose an on-demand preview of the actual published output. The Queue view owns one asynchronous thumbnail request and retires it when the preview closes, the job is cleared or navigation leaves Queue. Clipboard extraction and publication remain independent of the scheduler. Starting queue work requires idle clipboard work; copying requires a stopped queue with no active process. Waiting jobs alone do not block copying. Queued Upscale retains the selected encoder policy and resolves it against the current discovered tool capabilities at launch. FIFO advancement waits for pending optional discovery when the next job requires it; explicit CPU and other operations do not require NVENC discovery.

Pass process arguments separately instead of constructing shell commands. Map streams by their probed indexes. Preserve request identity, cancellation and completion routing when adding background work. Frame Capture also has dedicated frame-index, preview and clipboard workers under `src/frame_capture/`; clipboard extraction does not publish a file.

## Interactive Frame Capture

`src/app/frame_capture.rs` owns renderer-independent editor state, debounce, step decisions and the worker lifecycle. Preview, index and clipboard work is tied to the originating editor identifier and source identity; preview and index generations also identify the exact request. Normal, queue and item-override editors retain separate state. Exact frame positions are independent of the formatted timestamp and decoded pixels. The legacy frame adapter routes active-editor actions, supplies notification callbacks and uploads egui textures only for accepted generations.

The existing `FramePreview` and `FrameNavigator` retain their bounded caches; no second decoding or neighborhood cache is used. Explicit position changes retire superseded work. Temporary navigation away suspends outstanding work while retaining accepted pixels and cached neighborhoods, and returning schedules any necessary work. Clipboard extraction remains full-resolution and independent of file output and queue jobs. A retired decode cannot claim clipboard publication; a native publication already claimed may finish. Pixel conversion occurs before opening or clearing the clipboard. During normal close, active preview, index and clipboard extractions receive cancellation without releasing their owners until terminal settlement; a retired clipboard publication cannot start and an already claimed native transaction is allowed to finish without blocking the UI thread. Read-only decode and thumbnail results are retired. Pending discovery and source probes finish without starting further work; batch inspection stops taking new files and drains in-flight probes. Native dialog results are discarded while closing.

## Native dialogs and preferences

`FileDialogOwner` owns one pending native request and completion channel. The GPUI root captures the actual `WindowOwner` from its window and dispatches the existing Windows COM implementation through GPUI's foreground executor, outside an application borrow. The native picker is parented to that window and publishes its result before waking the root. A close request cannot remove the parent until the picker returns. During confirmed shutdown, its result is discarded. There is no unparented fallback. The retained adapter uses the same dialog types and test backend; its normal-form presentation remains until those forms are ported.

`src/app/dialogs.rs` builds and settles typed requests. Input requests capture the navigation revision and accepted source identifier; a retired context cannot receive a result even after returning to the same route. Output results target one operation and editor session. Accepted native input and GPUI ExternalPaths drops use the same application admission gate in `src/app/source.rs`. The root captures drag context at entry and rejects retired or unavailable contexts at drop. The source session remains authoritative until a replacement probe publishes; closing a source retires pending inspection and frame work without mutating queue jobs. Batch selection preserves every path in order and uses the existing batch inspection owner. Accepted paths are routed to the existing source, batch and independent editor owners. Only accepted selections update the remembered directory, even when subsequent media inspection fails. Cancellation, failures and stale results do not change directory history. Native output folder actions carry a `PathBuf` through the existing queue effect and report failures through queue feedback rather than logging alone.

`Application` owns `AppSettings`. `src/settings.rs` loads and atomically replaces `%APPDATA%\Apollo\data\settings.json`. A missing file uses defaults; a malformed or unreadable file uses defaults with an actionable warning and is not rewritten merely by loading it. Unavailable remembered directories fall back to a valid current source or draft directory. Changed preferences are saved after accepted selections; a failed write keeps the in-memory selection and offers retry. The previous eframe storage format was a RON string map in `app.ron` with JSON under `apollo.settings.v1`. The prior manifest did not enable eframe's `persistence` feature, and the offline dependency graph has no RON parser. Existing `app.ron` files, if present from other builds, remain untouched and are not imported; remembered directories from those builds reset once. No media, queue history or operation drafts are stored in this file. Appearance preferences are U07.

## Operation contracts

| Operation | Contract |
| --- | --- |
| Audio Mix | Mix selected embedded audio tracks into one AAC stream while copying the video. |
| Upscale | Fit video within the selected bounds, preserving aspect ratio, with H.264 or H.265 encoding. |
| Remux | Copy compatible streams into MP4 or MKV without re-encoding. |
| Audio Extract | Map one selected audio stream to original MKA, AAC or FLAC output. |
| Frame Capture | Extract one video frame as PNG or JPEG; preview and clipboard paths have separate lifecycles. |

Each operation owns its editable configuration in `draft.rs`, alongside its request model, validator, command builder and preparation function. Normal forms and queue and batch editors use the same typed request construction. `src/media/output_name.rs` owns shared filename stem and directory editing; the selected operation supplies the extension. Invalid editable text stays in the draft until corrected. Audio Mix caches pure readiness validation and invalidates it when draft or relevant source metadata changes. Upscale uses the current discovery capability state: explicit CPU is available while NVENC is pending, whereas Auto and explicit NVENC wait for settlement. Queue execution repeats the applicable validation before starting work. Extend these paths instead of creating alternate processing pipelines in UI code.

## Media-tool discovery

`src/app/discovery.rs` owns the discovery lifecycle, including checking, ready and unavailable states, the active attempt and capability settlement. `src/media/tools.rs` resolves FFmpeg and FFprobe and performs bounded version validation. Apollo first validates the complete pair beside its executable. If neither file exists there, it resolves both on PATH. A partial or invalid adjacent pair is reported as an error without falling back to PATH. Retry uses the same policy.

One background worker validates the base tools, publishes their paths, then checks optional NVENC capabilities. Retry is single-flight; the owner rejects stale attempts and capabilities for a different tool pair. A capability failure after base discovery leaves the base tools usable. Encoder capability results are cached by resolved FFmpeg path, file size and modification time. This identifies the runtime cache entry; release staging separately verifies the pinned archive checksum. The distribution contract lives in [media-tools.json](../distribution/media-tools.json), with measured compatibility in [the acceptance record](../distribution/media-tools-acceptance.md).

## Worker notifications

Workers publish results to their existing channels before invoking a completion callback. When a panic is reported through disconnection, the worker drops its result sender before notifying. The callback carries no application state; the owner consumes and validates the result on the application side. GPUI workers signal the bounded wake channel; retained egui consumers still supply their repaint callback. `MediaProcessWake` carries process progress and terminal events. `MediaProgressWakeOwner` coalesces progress notifications at 34 ms, rejects stale operation generations and wakes immediately on terminal events. The bounded channel retains a pending signal rather than a result; each owner retains and validates the actual result. A full channel already guarantees a pending wake, and a closed channel safely discards the notification. Idle workers do not schedule periodic scans. Frame Capture returns debounce deadlines to the adapter, which schedules delayed repaints.

## Queue and batch ownership

`src/app/queue.rs` owns application queue commands, edit admission and settlement, and the active-job notification channel. It passes typed requests and commands to the single scheduler and supplies renderer-neutral wake callbacks. Queue and clipboard start guards read the existing scheduler and clipboard work state directly. `src/app/editor.rs` owns fixed-source draft state and request construction shared by queue and batch editors; textures and source presentation remain in the adapter.

`src/ui/queue.rs` renders the GPUI Queue route from borrowed scheduler records. It groups jobs by lifecycle state without retaining another snapshot, keeps scheduler order and uses stable `JobId` element identities. The root routes Back and Add files through existing navigation and native intake; a suspended batch blocks new intake. The shell count still derives from `MediaQueue::pending_count()`, and foreground worker notifications refresh it independently of the visible route. The root dispatches scheduler actions through `Application::queue_action`, with readiness and active ownership derived from `MediaQueue`. Active progress and cancellation are scoped to the current `JobId`; confirmed bulk cancellation stops advancement and retains the active execution until settlement. Waiting and terminal job management actions are not yet ported. The replaced egui queue list and row geometry are removed; the retained legacy adapter still supports unmigrated editor, confirmation and preview regression coverage.

`MediaQueue` owns queued request snapshots, monotonic `JobId` values, source revalidation, sequential advancement, cancellation, terminal history, and atomic batch insertion. Single and batch admission require the source identity retained at inspection, validate it against the request and current filesystem, and apply the operation validator and output preflight without staging files. Batch admission checks all candidates and the full ID range before appending jobs; queue edits revalidate against the retained identity. Launch still rechecks source and destination. Queued jobs use `MediaExecution` for processing and staged-output publication. Queue progress and completion are routed by the active `JobId`; repainting a Queue or Batch surface must not inspect media or touch the filesystem. Tool readiness gates new launches, not settlement. If readiness is lost during a run, the active job settles without cancellation and automatic advancement stops, preserving waiting jobs for an explicit restart.

Waiting jobs can be reordered or removed during execution, including while stopping after current. Reordering swaps adjacent Waiting jobs without moving active or terminal records. Editing requires a stopped queue with no active execution, including cancellation settlement. Queue-row Edit settings and the loaded-source queued-item selector hydrate the same retained source and immutable request without another FFprobe invocation. Saving revalidates the source, request and destination against other pending jobs, and replaces the request atomically without changing its `JobId`, source or position. Rejected saves preserve the draft and stored job; Cancel leaves the job unchanged. Entry origin owns the return route.

`Add to queue` keeps the source and operation active, increments the pending count, and shows operation-local feedback. Pending counts include Waiting and Running jobs only. Ordinary submissions may share a requested filename and use numbered collision handling. Retry revalidates the retained source and request against current encoder capabilities, existing output and pending destinations, appends a new Waiting job with a new ID, and retains the failed or cancelled record. An exact retry reservation prevents further submissions to its requested name until removal or terminal settlement. Retry never starts a stopped queue. Its output collision policy is carried through preparation to no-replace publication; a destination claimed after admission fails safely rather than being renamed. Completed rows display the actual published path.

`src/app/batch.rs` owns temporary batch setup, inspection settlement, shared defaults, overrides, inclusion and admission. Stable `BatchItemId` values associate row actions, inspection results and admission errors with their originating item; the worker index is resolved through the inspection session’s item IDs. It applies one shared operation and source-independent defaults, then projects and validates a request independently for each inspected source. Per-file overrides survive later shared-default changes. `BatchInspectionOwner` supplies at most two concurrent probes per active inspection session. Retirement cancels remaining work and discards late results; an already-running probe can finish. Appending sources uses the same inspection engine and preserves the current operation, defaults, inclusion choices, and overrides. Repeated sources are allowed as independent items, but included output destinations must differ from each other and from pending queue reservations. Batch readiness is reconciled on inspection, settings, membership and reservation changes, using queue admission validation without staging output. Submission rechecks the filesystem and retains the batch on failure. Ordinary single submissions retain numbered-output handling. No queued job exists until `MediaQueue` accepts the complete included batch atomically.

Queue controls:

- `Cancel job` requests cancellation of the active job and continues advancement only while the queue is Running. The active job remains owned and displays Cancelling until process and output settlement finishes.
- `Stop after current` lets the active job finish, stops advancement, and preserves Waiting jobs.
- `Cancel queue` requires confirmation, stops advancement, marks all Waiting jobs Cancelled and requests active cancellation. An already claimed terminal result is not replaced by cancellation.
- `Clear finished` removes every terminal job, including failures.
- Queue history is application-scoped for the current session and is not restored after exit. Back, Add files, source replacement and tool changes retain all jobs. Clear finished removes terminal records only, never output files. Opening Queue from batch setup suspends the view without retiring the batch; Back restores it. New file intake is disabled while that batch is suspended to avoid replacing the retained draft.

## Upscale sizing and encoding

`src/upscale/sizing.rs` calculates even output dimensions that preserve the source aspect ratio within the selected bounds. Presets account for orientation; custom width and height must be positive and even and are never swapped. Sizing rejects bounds that cannot enlarge the source without exceeding a boundary or reducing a source dimension through quantization. Execution uses the calculated dimensions.

Scaling uses `scale=<width>:<height>:flags=lanczos`. Encoder selection does not enable hardware decoding or CUDA/NPP scaling.

| Backend | H.264 | H.265 | Quality policy |
| --- | --- | --- | --- |
| CPU | `libx264`, CRF 18 default | `libx265`, CRF 20 default | CRF 0..51, `slow` preset |
| NVIDIA NVENC | `h264_nvenc`, CQ 16 default | `hevc_nvenc`, CQ 16 default | CQ 1..51, `p5`, VBR, explicit CQ |

Lower quality numbers favor quality over file size. CRF and CQ are not interchangeable scales. State retains values independently for each codec/backend, alongside the last custom boundary and manual output name.

The shared media-tool owner checks compiled NVENC availability and runs bounded, hidden, minimal real encode probes off the UI thread. H.264 and H.265 results are independent and cached for the resolved FFmpeg identity. Base tool discovery can finish before these probes: normal workspace use and CPU Upscale remain available while Auto and explicit NVENC show checking state. Auto selects NVENC only after success; explicit unavailable NVENC retains diagnostics and never silently falls back. Do not probe on repaint or command construction.

The measured NVIDIA baseline and API version are recorded in [the media-tool acceptance record](../distribution/media-tools-acceptance.md). Encoder inventory alone cannot prove runtime driver compatibility. If initialization fails, Auto resolves to CPU; explicit NVIDIA selection retains the real probe error. An error after an encode has started remains a job failure, not a silent CPU rerun.

### Pixel format and color limits

The probe retains pixel format, derivable bit depth, range, matrix, transfer, and primaries. Shared Upscale validation resolves the output format for both ready feedback and execution:

- 8-bit `yuv420p` is supported on CPU and NVENC. `nv12` uses `yuv420p` on CPU or `nv12` on NVENC; `yuvj420p` is CPU-only.
- Supported 10-bit 4:2:0 sources require H.265, using `yuv420p10le` on CPU or `p010le` on NVENC. PQ/HLG signaling requires known compatible 10-bit input.
- Unsupported or contradictory known format information is rejected. When both pixel identity and depth are absent, strict FFmpeg format selection preserves the filter output rather than guessing an 8-bit format.
- Commands use strict `-pix_fmt` selection and map only available color values. External encoder/hardware limitations can still fail execution instead of silently choosing a different format.
- Mastering-display and content-light side data are not explicitly preserved or verified. Format checks alone cannot establish full HDR preservation or visual fidelity.

## Native interface and resources

GPUI resolves the shared typography roles in `src/ui/design.rs` and registers Geist Variable and Fira Code Regular at startup. Geist is the UI family; Fira Code is the fixed lowercase wordmark family. The retained egui `src/ui/fonts.rs` embeds IBM Plex Sans and Fira Code for its remaining views and tests. Missing compile-time font assets fail the build. Keep Fira Code after legacy rendering is removed, and preserve the licenses and asset identities documented in [the font notes](../assets/fonts/README.md).

Keep source inspection, preview decoding and media processing off the UI thread. `MediaProgressWakeOwner` coordinates progress notifications; retained state should drive the interface between updates.

`src/ui/icon.rs` embeds `assets/apollo-logo.png` for the native window. On Windows, `build.rs` compiles `assets/apollo.rc` using Cargo's package version. The resource script embeds `assets/apollo.ico` and the executable's Windows version information. The NSIS installer also consumes the ICO. Documentation artwork in `assets/docs/` is not used by the application build.

## Distribution boundary

`distribution/` owns the media-tool pin and compatibility evidence, `scripts/` owns staging and release tooling, and `installer/windows/` owns the NSIS installer. The installed and portable distributions include the pinned media tools and required license material. Cargo builds do not download or stage those tools.
